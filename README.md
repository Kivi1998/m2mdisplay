# M2M Display

自研的 MacBook Pro ↔ iMac 低延迟屏幕共享工具，用来替代 AirPlay 扩展显示器（"Mac 用作 AirPlay 接收器"）方案。核心诉求：鼠标光标的响应延迟必须明显优于 AirPlay。

## 背景

原方案是用 macOS 的 AirPlay 接收器功能把 iMac 变成 MacBook Pro 的扩展屏幕。实测发现哪怕两台机器之间是雷雳线直连（Thunderbolt Bridge，亚毫秒级网络延迟），鼠标在 iMac 屏幕上的响应依然能感觉到明显卡顿——根因是 AirPlay 把光标"烤"进了视频帧里，鼠标移动要跟着"抓屏 → 硬件编码 → 网络传输 → 解码 → 渲染"这条完整流水线走，而不是被单独处理。

## 架构

一个 Sender + 一个 Receiver，各自独立进程，通过雷雳桥接网络（10.10.10.0/24）直连，不经过任何第三方服务：

```
MacBook Pro（Sender）                          iMac（Receiver）
 ├─ CGVirtualDisplay 创建虚拟显示器
 ├─ ScreenCaptureKit 抓屏（关闭系统光标）
 ├─ VideoToolbox HEVC 硬件编码 ────────视频通道(TCP)────────▶ VideoToolbox 解码 → 全屏渲染
 └─ CGEventTap 监听真实鼠标位置 ───────光标通道(UDP)────────▶ 独立图层叠加渲染
                                    ◀──────ACK 回执(UDP)────── 渲染完成后立即回执
```

**关键设计**：光标位置走独立的 UDP 通道，不等视频帧、不进编解码流水线，这是延迟大幅领先 AirPlay 的核心原因。

## 延迟实测

用"渲染完成回执"方案测的：iMac 接收端每次真正把光标像素画到屏幕上后，立即回一个 UDP 确认包给 MacBook；MacBook 用自己单机的时钟算这段往返时间，不需要两台机器时钟同步。50 个样本，测试期间真实移动物理鼠标：

| 指标 | 数值 |
|---|---|
| 中位数 (p50) | **0.99 ms** |
| 95 分位 (p95) | 2.12 ms |
| 平均值 | 1.38 ms |
| 最小值 | 0.68 ms |
| 最大值（单次异常值） | 9.83 ms |

这是**往返**（鼠标移动 → 渲染 → 确认回来）时间，单程感知延迟（鼠标动 → 屏幕真正变化）约为这个数字的一半，中位数在 **0.5ms 量级**。

### 对比

下面 AirPlay / Luna Display 的数字来自公开资料和行业口碑，**不是用同一套方法直接测出来的**，只能作为量级参考，不是严格意义上的同基准对比：

| 方案 | 典型延迟量级 | 备注 |
|---|---|---|
| AirPlay 扩展屏幕 | 几十毫秒 | 光标随视频帧走完整编解码流水线 |
| Luna Display（商业产品） | 30–60ms（官方/口碑数据） | 专用硬件狗 + 自研编解码器，仍是流媒体架构 |
| **M2M Display（本项目）** | **~0.5ms 单程（实测中位数）** | 光标独立通道，绕开编解码流水线 |

数量级差距的核心原因就是架构选择：M2M Display 的光标延迟只取决于"发一个坐标包 + 本地画一个图层"，跟视频编解码延迟完全解耦；AirPlay/Luna Display 无论怎么优化编解码器，光标本质上仍然是视频流的一部分。

## 已知问题

- **显示尺寸与清晰度必须分开配置**：虚拟桌面固定为“看起来像 1920×1080”，保持合适的文字和窗口大小；HiDPI 后备缓冲使用 3840×2160 像素，让每个逻辑点由 2×2 个像素绘制。启动时会校验逻辑尺寸、后备像素和 2× 倍率，避免静默退回模糊的 1× 1080p。
- **iMac 面板仍有一次系统缩放**：iMac 面板原生为 4480×2520，而当前“看起来像 1920×1080”的 macOS 后备缓冲是 3840×2160，WindowServer 最终会缩放到物理面板。这个缩放幅度远小于旧版把 1920×1080 放大到全屏造成的模糊。
- **逃生开关依赖辅助功能权限**：接收端窗口会覆盖整个屏幕，内置了三击 Esc 退出的逃生开关，但需要先在 iMac 上单独授权"辅助功能"权限才能生效；未授权时只能远程 kill 进程或使用 Mission Control / Cmd+Tab（因为窗口层级用的是 `.floating`，不会挡住系统级切换）。
- **首次运行需要授权两个系统权限**：Sender 所在的终端/宿主进程需要"输入监控"（Input Monitoring）权限才能收到全局鼠标事件；两边首次运行 ScreenCaptureKit 相关功能需要 Screen Recording 权限。
- **固定 IP 假设**：MacBook Pro 固定为 `10.10.10.1`，iMac 固定为 `10.10.10.2`（雷雳桥接网络地址），换设备或网络配置需要改 `Sources/M2MShared/NetworkConfig.swift`。

## 使用方法

```bash
swift build

# iMac 上（接收端，需要先 scp 编译产物过去）
.build/debug/M2MReceiver

# MacBook Pro 上（发送端）
.build/debug/M2MSender
```

本机自环测试（发送端和接收端跑在同一台机器上）：

```bash
M2M_RECEIVER_HOST=127.0.0.1 .build/debug/M2MSender
```
