# M2M Display

M2M Display 是一套面向 MacBook Pro 与 iMac 的低延迟扩展显示工具，用于替代 macOS 的 AirPlay 接收器方案。项目通过雷雳桥接网络直连两台设备，不依赖第三方服务，并将鼠标光标从视频流中分离，以获得明显低于 AirPlay 的光标响应延迟。

## 设计背景

原方案使用 macOS 的 AirPlay 接收器功能，把 iMac 作为 MacBook Pro 的扩展显示器。即使两台机器通过雷雳线直连，网络往返延迟已低于 1 毫秒，鼠标在 iMac 上仍能感到明显迟滞。

原因是 AirPlay 会把光标合成进视频帧。每次鼠标移动都必须经过“抓屏 → 编码 → 网络传输 → 解码 → 渲染”的完整视频流水线。M2M Display 则使用独立的光标通道，只传输位置数据，并在 iMac 上单独绘制箭头光标。

## 系统架构

系统由发送端和接收端两个独立进程组成，通过 `10.10.10.0/24` 雷雳桥接子网通信：

```text
MacBook Pro（发送端）                           iMac（接收端）
 ├─ CGVirtualDisplay 创建虚拟显示器
 ├─ ScreenCaptureKit 抓取屏幕，不包含系统光标
 ├─ VideoToolbox HEVC 实时编码 ───── 视频通道（TCP）────▶ VideoToolbox 解码 → 全屏渲染
 └─ CGEventTap 监听真实鼠标位置 ───── 光标通道（UDP）───▶ 独立图层绘制箭头光标
                                      ◀── 确认通道（UDP）── 图层更新提交后立即回执
```

核心设计如下：

- 视频使用 TCP 可靠、有序传输，雷雳桥接链路无需为无线网络丢包配置大型抖动缓冲区。
- 光标位置使用 UDP 独立传输，新位置无需等待旧位置或视频帧。
- 接收端提交光标图层更新后立即回执，发送端使用单机时钟计算处理与传输往返时间。
- 虚拟桌面保持“看起来像 1920×1080”的尺寸，同时使用 2 倍 Retina 后备像素提高文字清晰度。

## 显示尺寸与清晰度

项目明确区分逻辑尺寸和后备像素：

| 项目 | 数值 | 作用 |
|---|---:|---|
| 逻辑桌面尺寸 | 1920×1080 点 | 决定文字、窗口和界面的视觉大小 |
| Retina 后备像素 | 3840×2160 像素 | 决定文字边缘和界面细节的清晰度 |
| 后备比例 | 2 倍 | 每个逻辑点使用 2×2 个像素绘制 |
| iMac 面板 | 4480×2520 像素 | 最终物理显示分辨率 |

因此，系统设置中会同时出现以下信息：

```text
分辨率：3840×2160
界面看起来像：1920×1080
```

这不会把文字缩小成原生 4K 尺寸。窗口布局和文字大小仍按 1920×1080 计算，3840×2160 只作为内部 Retina 绘制缓冲区。发送端启动时会验证逻辑尺寸、后备像素和非镜像状态；若系统退回模糊的 1 倍模式，程序会直接报错退出。

iMac 面板原生分辨率为 4480×2520，窗口服务器仍需把 3840×2160 后备画面缩放到物理面板。该缩放幅度远小于旧版直接把 1920×1080 像素放大到全屏产生的模糊。

## 延迟实测

接收端在主线程提交光标图层位置更新后立即发送 UDP 确认包。发送端使用自己的单机时钟计算“鼠标事件 → 网络传输 → iMac 提交图层更新 → 确认返回”的往返时间，因此无需同步两台机器的时钟。

以下数据来自移动真实物理鼠标时采集的 50 个样本：

| 指标 | 数值 |
|---|---:|
| 中位数（第 50 百分位） | **0.99 毫秒** |
| 第 95 百分位 | 2.12 毫秒 |
| 平均值 | 1.38 毫秒 |
| 最小值 | 0.68 毫秒 |
| 最大值（单次异常值） | 9.83 毫秒 |

以上数据衡量事件处理、网络传输和图层更新提交的往返时间，不包含 macOS 合成器排队、面板扫描和像素响应时间，因此不能直接等同于真实上屏延迟或用户感知延迟。

### 方案对比

AirPlay 和 Luna Display 的数据来自公开资料及行业使用反馈，并非使用本项目测量方法得出的同基准结果，只能用于判断延迟量级。

| 方案 | 典型延迟量级 | 说明 |
|---|---:|---|
| AirPlay 扩展显示 | 数十毫秒 | 光标随视频帧经过完整编解码流水线 |
| Luna Display | 30～60 毫秒 | 使用专用硬件和自研编解码器，仍属于视频流架构 |
| **M2M Display** | **0.99 毫秒提交往返中位数** | 光标使用独立通道；该数据不包含最终合成与面板显示时间 |

## 环境要求

- 发送端：MacBook Pro，负责创建虚拟显示器、抓屏、编码和鼠标监听。
- 接收端：iMac，负责解码、全屏渲染和光标叠加。
- 系统：当前私有接口声明已在 macOS 26.5.2 与 Xcode 26.6 环境验证。
- 网络：雷雳桥接，MacBook Pro 使用 `10.10.10.1`，iMac 使用 `10.10.10.2`。
- 工具链：Swift 5.10 或兼容版本。

## 权限配置

发送端首次运行前需要授予以下权限：

1. MacBook Pro 上运行发送端的终端或宿主进程需要“屏幕与系统音频录制”权限。
2. MacBook Pro 上运行发送端的终端或宿主进程需要“输入监控”或“辅助功能”权限，才能监听全局鼠标事件。

iMac 接收端使用前台窗口内部的键盘监听，不需要“辅助功能”权限。修改发送端权限后应重新启动对应进程。

## 构建与运行

### 构建调试版本

```bash
swift build
```

### 构建发布版本

```bash
swift build -c release
```

### 在 iMac 上运行接收端

先把接收端可执行文件复制到 iMac，再启动进程：

```bash
ssh 10.10.10.2 'mkdir -p ~/m2mdisplay'
scp .build/release/M2MReceiver 10.10.10.2:~/m2mdisplay/M2MReceiver
ssh 10.10.10.2 '~/m2mdisplay/M2MReceiver'
```

### 在 MacBook Pro 上运行发送端

```bash
.build/release/M2MSender
```

启动成功后，日志应包含：

```text
active Retina mode: looks like 1920x1080, backing pixels 3840x2160
```

### 本机回环测试

先在本机为接收端指定确认包回送地址并启动，再为发送端指定接收地址：

```bash
M2M_SENDER_HOST=127.0.0.1 .build/debug/M2MReceiver
M2M_RECEIVER_HOST=127.0.0.1 .build/debug/M2MSender
```

两个地址都可以通过环境变量覆盖：

- `M2M_RECEIVER_HOST`：发送端连接的接收端地址，默认值为 `10.10.10.2`。
- `M2M_SENDER_HOST`：接收端发送确认包的发送端地址，默认值为 `10.10.10.1`。

## 操作与退出

- 发送端建立连接后，iMac 接收端会自动显示投屏画面。
- MacBook Pro 停止投屏、退出发送端或连接意外中断后，iMac 会立即隐藏投屏窗口，恢复原生桌面、菜单栏、程序坞和鼠标；接收进程继续在后台监听，下次连接时自动重新显示。
- 把鼠标移入虚拟显示器后，iMac 会显示独立渲染的箭头光标。当前版本尚不传输文本、手形或缩放等光标形态。
- 把鼠标移回 MacBook Pro 自带屏幕后，iMac 上的叠加光标会自动隐藏。
- 接收端位于前台时会隐藏 iMac 原生菜单栏、程序坞和原生鼠标，只保留远程桌面画面与独立渲染的箭头光标。
- 在 iMac 上 2 秒内连按三次 Escape，可作为紧急退出接收端的备用方式；正常停止投屏不需要按 Escape。
- Cmd+Tab 切换到其他应用时，接收端会恢复 iMac 原生光标并降低窗口层级；切回接收端后会重新进入沉浸显示。

## 故障排查

### 画面尺寸正确但文字模糊

检查发送端启动日志和系统显示信息。正确状态必须同时满足：

```text
逻辑尺寸：1920×1080
后备像素：3840×2160
后备比例：2.0
镜像状态：关闭
```

若后备像素仍为 1920×1080，说明系统没有激活 HiDPI 模式，当前版本会拒绝继续启动。

### 只有画面左上角被放大显示

接收端的视频格式描述与发送端像素尺寸不一致。当前实现要求接收端按 3840×2160 解释 HEVC 码流，光标坐标仍使用 1920×1080 点。

### 发送端一直等待连接

确认 iMac 接收端已经启动，并检查雷雳桥接地址：

```bash
ping 10.10.10.2
```

### 没有鼠标事件

检查发送端宿主进程是否拥有“输入监控”或“辅助功能”权限。授权后必须完全退出并重新启动进程。

### 无法用 Escape 退出接收端

确认接收端仍是 iMac 前台应用，并检查启动日志是否包含 `escape hatch armed`。也可以使用 Cmd+Tab 切换到其他应用，或通过 SSH 终止接收端进程。

## 项目结构

```text
Sources/
├── CGVirtualDisplayShim/  CoreGraphics 私有虚拟显示接口适配层
├── M2MShared/             网络地址、数据协议和共享配置
├── M2MSender/             虚拟显示、抓屏、编码、网络发送和鼠标监听
└── M2MReceiver/           网络接收、解码、全屏渲染和光标叠加
```

## 当前限制

- 虚拟显示器依赖 CoreGraphics 私有接口，系统升级后需要重新验证接口签名和行为。
- 雷雳桥接默认地址为 `10.10.10.1` 和 `10.10.10.2`；更换网络规划时可设置 `M2M_SENDER_HOST` 和 `M2M_RECEIVER_HOST`，无需修改源码。
- iMac 原生面板为 4480×2520，1920×1080 视觉尺寸对应的 Retina 后备画面仍会经过一次系统缩放。
